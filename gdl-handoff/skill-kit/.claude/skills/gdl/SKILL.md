# /gdl — GDLオブジェクトをArchicadに自動生成するスキル

ユーザーが「/gdl 幅900 奥行450 高さ1800の3段本棚」のように依頼したら、
GDLオブジェクトを設計し、Archicad の埋め込みライブラリに登録して配置するところまで自動で行う。

## 前提(毎回最初に確認)

このスキルフォルダにある `gdl_to_archicad.py` を使う。まず準備確認を実行する:

```
python .claude/skills/gdl/gdl_to_archicad.py check
```

(`python` が無ければ `py` を試す。) NG が出たら、そのメッセージの指示をユーザーに日本語で伝えて止まる。
OK なら次へ。Archicad複数起動の指摘があれば `--port` を全コマンドに付ける。

## 手順

### 1. 要件の整理

依頼文から以下を決める。曖昧でも合理的な既定値で進め、決めた値を最後に報告する
(質問はどうしても必要な場合に1回だけ):

- 寸法: 幅 a / 奥行 b / 高さ zzyzx (メートル単位。「900」等はmm指定とみなして0.9mに変換)
- 可変にすべきパラメータ (段数・板厚など)。パラメータ名は英小文字 (例: num_shelves, thickness)
- 材質・ペンはArchicadの組み込みパラメータに任せ、`MATERIAL` はパラメータ化した変数で指定する

### 2. GDLスクリプトを書く

作業フォルダに `<オブジェクト名>/` を作り、スクリプトを設計する。ルール:

- 単位はメートル。3Dは `BLOCK`/`PRISM_`/`CYLIND`/`ADD`/`ROT`/`DEL` 等の基本コマンド中心に、
  確実に動く範囲で書く (凝った新しいコマンドより互換性優先)
- 2Dスクリプトは原則 `PROJECT2 3, 270, 2` の投影1行でよい
- `FOR〜NEXT` の繰り返し、`IF` の分岐は使ってよい。各行に日本語コメント(`!` 記法)を付ける
- パラメータの整合性はマスタースクリプトで `PARAMETERS`/`LOCK` を使わず、まずは単純に保つ

### 3. XMLを作る

`template.xml` (このスキルフォルダ内) をコピーして `<オブジェクト名>/<オブジェクト名>.xml` を作り、
以下を差し替える:

- `Script_3D` / `Script_2D` の CDATA 内に手順2のスクリプト
- `<Parameters>` にパラメータ定義 (Length=長さ, Integer=整数, RealNum=実数, Boolean=真偽,
  Material=材質 等。`a`/`b`/`zzyzx` は必ず残す)
- UnID のGUIDは新しいGUIDに差し替える (`python -c "import uuid;print(str(uuid.uuid4()).upper())"` で生成)

### 4. 変換してArchicadに投入する

```
python .claude/skills/gdl/gdl_to_archicad.py build --xml <オブジェクト名>/<オブジェクト名>.xml --name <オブジェクト名> --x 0 --y 0 --z 0
```

成功すると: gsm変換 → 埋め込みライブラリ登録(「Claude GDL」フォルダ内) → ライブラリ再読込 →
原点(0,0,0)に配置、まで自動で行われる。

### 5. エラー時の自己修復

**LP_XMLConverter が XML エラーを出した場合** (最重要):

1. エラーメッセージの行番号・セクション名を読んで XML を修正して再実行する。
2. 構造レベルのエラー (SectVersion / Symbol属性 / Ancestry 等) が解決しない場合は、
   実物のXMLを手に入れて構造を合わせる:
   - PC内から適当な既存 .gsm を1つ探す (`dir /s /b C:\*.gsm` は遅いので、まず
     Archicadインストールフォルダ・書類フォルダ・ダウンロードフォルダを探す)。
   - 見つかったら: `python .claude/skills/gdl/gdl_to_archicad.py template --seed <見つけた.gsm> --out .claude/skills/gdl/template_generated.xml`
   - 生成された `template_generated.xml` の構造 (Symbol属性・SectVersion・Ancestry・ParamSection
     ヘッダー) を正として、スクリプトとパラメータだけ差し替えた XML を作り直して再実行。
   - 以後この環境では `template_generated.xml` を優先テンプレートとして使う。
   - .gsm がどうしても見つからない場合は、ユーザーに「Archicadで適当なオブジェクトを1つ選んで
     [ファイル > ライブラリとオブジェクト > 選択内容に名前を付けて保存] で .gsm を保存してください
     (初回のみ)」と依頼する。
3. 「同名オブジェクトが既にある」エラーは `--name <名前>_v2` のように新しい名前で再実行する。

**接続系エラー**は check と同じ対処 (Archicad起動・Tapir導入・ポート指定) を案内する。

### 6. 完了報告

日本語で以下を報告する:

- 生成したオブジェクト名と配置座標 (原点に配置した旨)
- 採用した寸法・パラメータの一覧 (ユーザーがオブジェクト設定ダイアログで変更できること)
- 気に入らない場合は要素を選択して削除、または[編集 > 元に戻す]で取り消せること
- 修正依頼は「/gdl さっきの本棚の棚板を5段にして」のように続けて頼めばよいこと
  (その場合は新しい名前 _v2 等で再生成する)

## 安全上のルール

- ユーザーのモデル要素を削除・変更しない。行うのは「埋め込みライブラリへの追加」と
  「新規オブジェクトの配置」のみ。
- 生成物はすべて埋め込みライブラリの「Claude GDL」フォルダにまとめる。
- 1回の依頼で配置するのは1個まで (数量指定があっても、まず1個置いて確認してもらう)。
